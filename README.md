# Webagent

A Chrome Manifest V3 side-panel agent for multi-step workflows on HTTPS websites. It acts in the tab you star (★) and can read text from up to five other open tabs (+) as context, asking OpenRouter for one action at a time. It drafts a 3–6 step plan before it starts, shows that plan as a checklist in the side panel, keeps the plan across steps and panel reloads, and ticks items off as it finishes them. It can think through a plan, click, type into ordinary text fields, read the full page text, scroll, wait for loads, navigate, and summarize. Every step lands in a timeline in the chat, with the current action pinned at the bottom while it runs. Each step sends the full action history — recent steps with their results and the page URL after each one, older steps condensed — so the agent does not forget what it already tried. It also receives an interactive-element map of the viewport (role, label, and centre coordinates) alongside the screenshot, which makes clicks far more accurate than vision alone. The Worker rejects a step that repeats an action the page did not respond to and asks the model to choose differently, and it refuses a premature `done` while plan items are unchecked. By default it shows the proposed action and screenshot for your approval; select **Continue to next step** once the page has settled. Opt-in **Full access mode** automatically executes actions without per-action approval, including clicks that may submit forms or make irreversible changes. It stops after 40 steps. The Stop button prevents subsequent actions, but an action already in progress may still finish. It cannot access Chrome internal pages, and it blocks typing into password fields and forms containing password inputs. Use only on sites and tasks you are authorized to automate.

## Install the extension

Download [dist/webagent-extension.zip](dist/webagent-extension.zip), unzip it, open `chrome://extensions`, enable **Developer mode**, and choose **Load unpacked** with the extracted folder. Pin the extension and click its icon to open the side panel. This is an unpacked developer build, not a Chrome Web Store publication. For a new ZIP after editing, run `cd extension && zip -r ../dist/webagent-extension.zip .`.

The default Worker is `https://webagent.amos-donn.workers.dev`. Select a page, enter an objective, and start; webagent writes a plan first and checks items off as it works. No accounts or sign-in. The extension requests Chrome site access as needed. Full access may pause when it encounters an origin that has not yet been granted; select Continue or approve the navigation to grant access. In review mode, review the proposed text, destination and screenshot marker before approving. In full access mode, actions are automatic and may be wrong; use it only when you accept that risk. A page can change after observation, and visual coordinates can be wrong; never approve an action without checking. If a click opens a new tab, select that tab before continuing. The agent does not automatically handle CAPTCHAs, authentication, payment details, downloads, or restricted pages.

## Configure your existing Worker and D1

1. `wrangler.jsonc` identifies your existing **webagent** D1 database and binds it as `DB`. Wrangler config is the deployment source of truth; verify the ID in Cloudflare Dashboard → D1 → webagent if your database changes.
2. Apply [migrations/0001_initial.sql](migrations/0001_initial.sql) to that database once using the D1 dashboard SQL console, or from an authenticated Wrangler installation run `npx wrangler d1 migrations apply webagent --remote`. This creates the `rate_limits` table. Do not apply this to a database you did not intend to modify.
3. In Worker → Settings → Variables and Secrets, add these **encrypted secrets**:
   - `OPENROUTER_API_KEY` — your OpenRouter API key. Store it as a Worker secret, not in the extension.


   The Worker uses `google/gemini-3.5-flash-lite`: a fast, low-cost vision model that supports the image and JSON request, routed to the highest-throughput provider (`provider: { sort: "throughput" }`). To change it, add an ordinary (non-secret) variable `OPENROUTER_MODEL` — for example `openrouter/free` for a zero-cost model, or `google/gemini-2.5-flash` for more capability. The model must accept image input and JSON output. Model pricing, availability and rate limits vary.
4. In Workers Builds, use the repository root and deploy command `npx wrangler deploy`. The config sets `keep_vars` to preserve dashboard variables and secrets. Make sure the build has a supported Wrangler version and that `DB` is still bound to the intended database after deployment. Apply the migration before deploying this version. Your existing push-to-main build can deploy it once these changes are committed and pushed; this project does not push or deploy automatically on its own.
5. Open `https://webagent.amos-donn.workers.dev/health` to check that the Worker responds, then test a simple workflow in Chrome.

## Privacy and limitations

When you start or continue a workflow, visible page text (up to 40,000 characters, trimmed to 12,000 for the model), the viewport screenshot, labels and coordinates of visible interactive elements, the current URL, the objective, the plan, and previous actions are sent to the Worker and OpenRouter and the selected model provider. Screenshots can contain sensitive information even when text is hidden. Do not use sensitive pages or enter secrets in objectives. Model output and website content are untrusted: prompt injection and incorrect actions are possible, and confirmation is not a guarantee of safety, and full access removes per-action confirmation entirely. Provider keys remain on the Worker. The D1 database stores only rate-limit counters; it does not store workflows. Your plan and its checkmarks live in Chrome extension local storage, are sent to the model with each step, and are cleared with **Clear** or replaced by the next task. There is no login, so anyone with your Worker URL can spend your OpenRouter quota: keep the URL private. Rate limits are basic and should not be treated as complete abuse protection. Deploy with appropriate access, monitoring, and quota controls before sharing publicly.

Provider references: [OpenRouter free router](https://openrouter.ai/docs/guides/routing/routers/free-router), [OpenRouter API](https://openrouter.ai/docs/api_reference/overview), [Cloudflare D1 migrations](https://developers.cloudflare.com/d1/reference/migrations/), [Workers Builds configuration](https://developers.cloudflare.com/workers/ci-cd/builds/configuration/).
